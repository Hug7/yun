# 5 预校验剪枝原则

- Status: accepted

## 5.1 原则

预检用于提前排除必然不可行的组合：预检判为不可行，该组合会被整格跳过，不再枚举槽位、不再做任何评估。因此预检只依据与求解状态无关的静态数据——场景输入、模型容量、站点准入等。

随求解过程变化的量（当前的资源占用、已经完成的提交）不参与预检。预检无法静态判定的，返回「未知」交给评估兜底，而不是判不可行。

## 5.2 理由

按占用做预检会过度剪枝：某个组合此刻不可行，可能只是因为能装下它的车型恰好被占满。整格剪掉后既不评估、也不保留「为什么不可行」，占用释放后无法恢复，只能等全量重算；同一个组合在不同时刻得到不同结论，还会让候选集依赖提交顺序。

少剪枝的代价是更多组合进入评估。这是刻意的取舍：预检负责静态不可行，动态判定留给评估与提交路径。

## 5.3 适用范围

该原则对组合级预检与槽位级预检同样成立：槽位预检同样只依据静态数据，不得因当前资源占用剪掉槽位；需要动态状态的判断交给评估与提交路径。槽位预检的具体条目在引入时补充。
